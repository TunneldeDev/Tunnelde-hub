# Host storage location metadata

`createHostStorageClient(host)` from `sdk/storage/locations/client.mjs` is separate from the plugin KV client. Its experimental `observe` and owner-bound `subscribe` require `storage.locations.read`. `schedule` and `cancel` additionally require `storage.locations.write` and native user confirmation. Paths and metadata never grant file or secret access.

Read the current opaque revision before submitting one to eight distinct `{category,target,migrate}` changes. The native dialog identifies the plugin and shows normalized source/destination and restart behavior; the SDK's default mutation deadline is 70 seconds. A successful plan returns `scheduled`, cancelling an unstarted plan returns `cancelled`, and declining returns `dismissed` with fresh metadata. No method restarts or immediately migrates. Concurrent changes fail with `storage.locations.conflict`; recovery artifacts are preserved and return `storage.locations.recoveryRequired`.

Snapshots contain eight ordered location categories, a pending plan or null, and a recovery flag. They never expose raw config/errors, recovery IDs, inventory or contents. Subscription reads are serial, cancel with their owner signal and may coalesce state. Cancellation before the publication fence prevents the write; after publication read the latest state instead of assuming rollback. Native capacity remains charged for unfinished blocking workers. DTOs and the schema are mirrored from the app, with drift and real native producer/SDK checks. Detect support using `api.describe` and consult the generated [API catalogue](../../../sdk/api.md).
