# 原生 Agent 适配器测试

[English](agent-testing.en-us.md)

`npm test` 会运行确定性的协议测试。原生测试需要显式指定可执行文件；没有对应环境变量
时跳过，不会自动发现 Agent 或复用用户登录。构建和测试使用 Node，不代表插件获准使用
系统 Node 运行时。

Pi 适配器的测试方式：

```powershell
$env:TUNNELDE_TEST_PI = 'C:/path/to/pi.exe'
node --test tests/pi-native.test.mjs
```

```sh
TUNNELDE_TEST_PI=/path/to/pi node --test tests/pi-native.test.mjs
```

测试在已忽略的 `.tmp/qa/` 下创建独立配置、会话目录和工作目录。本机回环 HTTP 模型端
返回可控的流式消息和工具请求，验证不发送消息的协议初始化、Unicode 流式回复、跨进程
继续原生会话、工具批准与拒绝、拒绝后文件未改变、模型错误传播，以及进程清理。
每次测试的 `result.json` 留在对应临时目录中，不需要真实模型凭据或真实模型输出。

市场 CI 在 Linux 和 Windows 上使用 Pi 0.85.1 的原生发布包执行该测试，下载后先核对固定
SHA-256。模型端点和配置均由测试创建，不需要模型服务凭据，也不通过系统 Node 子进程
运行 Pi。

这些证据覆盖该版本的原生协议适配，不证明真实模型登录、SSH 传输、应用进程管理器、
桌面聊天交互或所有 Agent 版本兼容；这些仍需分别验收。不能将模拟协议或回环模型测试
通过描述为本地／远端真实认证对话已完成。

## 桌面与 SSH 验收

适配器测试与桌面验收覆盖不同边界。针对每个已发布的助手包，使用独立应用数据目录，记录
安装包摘要、应用源码／二进制及 agent／运行时版本。只连接明确授权且已验证主机密钥的
测试主机，测试文件放在有独立归属记录的唯一目录中。不复用已有 agent 登录，不更改服务、
系统运行时和配置。

通过应用实际聊天控件验证以下行为：

- 在运行位置中选择已保存或已连接的主机。主目录、工作目录和授权范围应来自该目标，
  不应靠手填内部会话 ID 绕过错误的默认行为。
- 发送前明确初始化。覆盖可执行文件／运行时缺失、运行时版本不支持和拒绝授权；失败后
  不允许发送，不能提交模型请求。使用已有运行时与上传 worker 文件分别取得相应授权。
- 验证回复及跨进程继续会话。API worker 的回环模型服务放在远端，避免桌面进程误调用
  本地端点也能通过测试。
- 验证工作区发现、相对路径和命令工作目录。工具允许／拒绝后，检查实际目标远端文件。
- 覆盖每种支持的权限模式。只读必须拒绝测试模型强行请求的修改；完全访问须明确确认；
  未配置独立审查者的代审批须回退人工。不支持的原生沙箱模式应在发送模型请求前拒绝。
- 在等待模型回复时断开 SSH，显示具体传输错误。以新的会话 ID 重连同一主机，重新初始化
  后发送一条新消息，确认历史保留且不会自动重发中断的请求。
- 删除测试会话，检查仅清理已记录且未改变的 worker 文件；停止自有进程，只删除自有测试
  目录。证据放在已忽略的 `.tmp/qa/`，不在日志和报告中记录凭据。

远端回环模型证明运行位置和传输行为，不证明公网模型认证。真实认证需要另行使用明确授权
的测试账户验收，在 PR 和更新说明中分别表述。
